## Known limits
- A request abandoned at the hard deadline keeps its worker thread until the server closes or the socket times out; its result is discarded and it was logged once. Closing test: a stalled server held open past the run (not written).
- Two origins of one host (http and https) whose robots.txt disagree can race: a refusal logged for one scheme between the other's budget check and its grant gives an audit "requested after robots refused" line. Closing test: a two-scheme race (not written).
- Changing the citewatch version mid-study changes the user agent, which the audit flags; a study keeps one version for its fetches (§13 runbook). Closing test: `doctor` warning on a user agent that differs from the fetch log (not written).
- Robots answers are kept per study, so a host's robots.txt is requested once per study; a fourth study fetching the same host would hit the audit's 3-request budget and read that host as disallowed. The flagship repo has one study. Closing test: share the robots store across sibling studies (not written).
- A 429 with a long Retry-After gives up on that page only; later pages on the host are still asked at 1 per second. A robots.txt answering 429 reads as allow-all (a 4xx, per §7.2). Calling `PoliteClient` directly with user info in a URL sends Basic auth (the CLI rejects such URLs through the Citation schema). Send jitter makes server-side arrival gaps 0.95–0.99 s although logged gaps pass. Closing tests: a host-level back-off after a long Retry-After; robots 429 as disallow; a margin sized from measured jitter (not written).

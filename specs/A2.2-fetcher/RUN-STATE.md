## Known limits
- A request abandoned at the hard deadline keeps its worker thread until the server closes or the socket times out; its result is discarded and it was logged once. Closing test: a stalled server held open past the run (not written).
- Two origins of one host (http and https) whose robots.txt disagree can race: a refusal logged for one scheme between the other's budget check and its grant gives an audit "requested after robots refused" line. Closing test: a two-scheme race (not written).
- Changing the citewatch version mid-study changes the user agent, which the audit flags; a study keeps one version for its fetches (§13 runbook). Closing test: `doctor` warning on a user agent that differs from the fetch log (not written).
- Robots answers are kept per study, so a host's robots.txt is requested once per study; a fourth study fetching the same host would hit the audit's 3-request budget and read that host as disallowed. The flagship repo has one study. Closing test: share the robots store across sibling studies (not written).
- A 429 with a long Retry-After gives up on that page only; later pages on the host are still asked at 1 per second. A robots.txt answering 429 reads as allow-all (a 4xx, per §7.2). Calling `PoliteClient` directly with user info in a URL sends Basic auth (the CLI rejects such URLs through the Citation schema). Send jitter on a warm connection can make server-side arrival gaps a little under 1 s (0.94–0.99 s seen under load) although logged gaps pass; the first request to a host is now spaced from its actual send. Closing tests: a host-level back-off after a long Retry-After; robots 429 as disallow; a margin sized from measured jitter (not written).
- Pass-4 surviving mutants each covered by another guard or with no stored effect (#7, #8, #18, #32), and the robots-loop seen-set (bounded by the 3-request budget). When a connect stall uses the whole deadline, a body that did arrive is still treated as a timeout and retried, within the budget. Closing tests: one per mutant (not written).
- The send-time lock has no test (removing it only matters for a send racing the deadline by microseconds); a Retry-After between 60 and 61 s is honoured. Closing tests: not written.
- Integer and short IPv4 forms (`2130706433`, `127.1`) are separate hosts from `127.0.0.1` for the rate limit (cited URLs use dotted names in practice). Closing test: normalise IPv4 forms with `ipaddress` (not written).
- IPv6 spellings of one address (`[::1]`, `[0::1]`) are separate rate buckets, like the IPv4 forms. A robots.txt starting with a byte-order mark reads as allow-all, as protego reads it (Google strips the mark). Closing tests: `ipaddress` normalisation; BOM stripping before protego (not written).
